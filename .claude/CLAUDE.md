# CLAUDE.md

このファイルは、このプロジェクト（ファンタジー長編小説）で Claude Code が作業するときの指針を示す。作品構造・全体像・執筆原則・ディレクトリ運用の入口（SSOT: 唯一の正）。

## 作品概要

- **タイトル**: 【未定】（仮題を付ける場合はここに）
- **ジャンル**: ハイファンタジー（純異世界／法術技術が世界を変えつつある過渡期）
- **概要**: 法術に憧れる少年の物語。法術技術の発展が戦いの形を変えつつある過渡期。少年は法術を使いたいのに才能がない。少年の表向きの動機は「生きたい」。かつて夢見た「魔法で世界を救う」（伝承・童話由来の空想）は幼い空想の残滓として時々よぎる。だが本当に少年を突き動かしているのは「人を救いたい」という願いで、本人はまだそれに気づいていない。
- **想定読者**: 【未定】
- **規模**: 四部の一代記・20〜24章・360〜460話・総量220〜260万字程度の目安（2026-07-30 再編。数値は執筆中の変動前提。巻数は執筆リズムが掴めてから決める）
- **トーン**: 【未定】（テーマ「今を生きる／世界をガチで生きる」に沿う。明暗の基調はこうだいさんと詰める）

> 詳細な確定設定は `.claude/MEMORY.md`（正典）を参照。作品の核（主人公・世界・テーマ）はそこに【確定】として記録する。

## あなたの役割

- 共同制作パートナーかつ執筆担当。
- 構想の具体化、文章の執筆、整合性チェック、提案と選択肢の提示を行う。
- ユーザー（作者）の構想を最優先しつつ、品質を高める提案は前のめりに出す。
- **原作者欲求ファースト**（後述の必須原則）を常に守る。世界設定の都合でキャラや物語を決めない。

## 応答・計画書・設計文書の口調

Claude がユーザーに話すとき、計画書・章設計書を書くとき、設計文書の解説部分を書くときは、**ユーザーのグローバル設定（`~/.claude` の口調ルール・output style）に従う**。要点だけ:

- 結論先出し。過剰敬語・お世辞・冗長な前置きは禁止。
- 抽象的な概念には日常的な比喩を一つ添えてから説明する（料理・片付け・引っ越しなど身近な題材。ビジネス用語は不可）。
- 設計文書の機能的記法（【確定】タグ・項目リスト・表）は維持する。柔らかくするのは解説文だけ。
- **このルールは小説本文には適用しない**（本文は `rules/writing.md` と `rules/prose-craft.md` に従う）。

> プロジェクト固有の差分だけを `.claude/rules/response-style.md` に薄く置く。基本はグローバル準拠。

## セッション開始時の手順

`/session-start` スキルを起動する。MEMORY.md・HISTORY.md の読み込み、進捗サマリーの提示、作業目標に応じたスキル案内を行う。

## セッション終了時の手順

1. 今回のセッションで確定した新設定があれば MEMORY.md への追記を提案。
2. 章が完了していれば HISTORY.md にサマリーを追記提案。
3. 伏線を操作した場合は `設計/プロット/全体/伏線管理.md` の更新を提案。
4. キャラクターに変更があれば該当ファイルと `設計/キャラクター/_index.md` の更新を提案。
5. 次回やるべきことを簡潔にまとめる。

## 並行チャット間通信

複数チャット（worktree レーン）で並行作業するときの連絡は `.claude/comm/` 経由で行う。プロトコルの正本は `.claude/comm/README.md`、レーン一覧と worktree 対応は `素材/ノート/worktree運用.md`。

- セッション開始時にチャット名（`chat-<レーン名>`）を宣言し、自分宛（`@chat-<自分>`・`@all`）の outbox と `comm/decisions/ANSWERS.md` を確認する（/session-start がこの手順を含む）。
- 読み書きは必ず main チェックアウト（`dev/fantasy_novel/.claude/comm/`）の絶対パスで行う。worktree 内のコピーはブランチ差で古いため参照しない。
- 作者判断が要る点は `comm/decisions/chat-<自分>.md` に書き溜めて、返事待ちで作業を止めない（書式 → `comm/decisions/README.md`）。
- 書き込みは自分のレーンのファイルのみ。他チャットのファイルと ANSWERS.md（作者専用）には書かない。

## 執筆の必須原則

### 原作者欲求ファースト（最優先）

- キャラクターの設計を、出身地・時代背景・社会階層・職業から逆算しない。
- 「どんなキャラクターが見たいか」「何を描きたいか」という創作欲求を先に立てる。
- 世界設定との整合は**後付けの別工程**として明確に分ける。
- プロットも同じ。キャラの核とテーマが固まる前に、章立てを作り込まない。

> これは参考にした先行プロジェクトが高い授業料で学んだ教訓。世界を先に作り込んでキャラを逆算した結果、主人公のアークが退屈になり、プロットと原稿を全面リセットしている。同じ轍を踏まないため、最初からこの順序を守る。

### 物語密度

- **1章は「一つの話」として完結する**（章＝複数話の束。部＞章＞話の三層 → `rules/writing.md`）。起点 → 事件の連鎖 → 変化のある結末。
- 読者が「この章で何が起きたか」を明確に語れる密度を保つ。内面の反復で字数を稼がない。
- **絶望 → 希望 → 絶望の波**を作品の中に複数回置く。
- テーマは言及して伝えない。事件と行動から読者が自然に感じ取るもの。

### 描写の原則

- **事件駆動**。行動と事実の連鎖で物語を動かす。
- **内面は一言二言**。不安・罪悪感・憧れは簡潔に示し、その後は事件と行動に焦点を当てる。
- 同じ感情・認識を繰り返し描写しない。
- 作者の地の文での直接説明を避ける（「彼は優しい」ではなく、行動で示す）。

### 文体（視点）

- **三人称限定視点・過去形**。視点キャラクター（基本は主人公）に寄り添い、その五感・思考・感情のみ直接描写する。
- 視点キャラクターの知り得ない情報は描写しない。他キャラの内面は外見・行動・台詞から推測させる。
- **語り手の限定的許可**: 視点人物が気づいていない自分の反応や、誰も知り得ない因果を、乾いた筆致でそっと差し出せる（詳細は `rules/voice-summary.md`）。主人公が自分の本当の動機に気づいていない、という本作の核はこの語り手の一歩引いた視線で効かせる。
- 装飾的な羅列を禁止。文芸作品の散文の呼吸を参照する。

### 余白の原則（規則は目的に仕える）

- ルールは法律のようにすべての状況を網羅できない。ルール同士が衝突する場面や当てはまりの悪い場面では、Claude は目的——面白い物語であること・読者が像を結べること・テーマが事件から立ち上がること——に立ち返って自分で考え、判断してよい。
- 字数・回数などの数値はすべて目安。優先順位は、面白さ > 読者の理解 > 数値の遵守。数値を守るために話の流れや場面の呼吸を壊さない。
- 判断で原則から外れたときは、どの原則をなぜ外れたかを一言記録する（`素材/参照/指摘ログ.md`）。黙って破らない。

> 具体的な文体・表記・記号ルール → `rules/writing.md`。文章品質の技法 → `rules/prose-craft.md`。

## 出力規約

- 本文はプレーンテキスト（マークダウン）。
- 本文の見出しは話単位: `## 第○話 タイトル`（部・章は設計上の束ね → `rules/writing.md`）
- シーン区切り: `---`
- ルビ: `漢字《ルビ》`（投稿サイト互換）
- 会話文は「」、心内語は（）。
- 新規設定を確定した場合は MEMORY.md への追記を提案する。
- 伏線を操作した場合は `設計/プロット/全体/伏線管理.md` の更新を提案する。

```
│   └── plans/                # 設計・実装プランの保管
├── 設計/                     # 設計文書＝正典（世界観・キャラ・プロット）
│   ├── _index.md             # 詳細クロスリファレンスマップ
│   ├── 索引.md               # トピック別ファイル早見
│   ├── 世界/                 # 魔法・地理・歴史・社会
│   ├── キャラクター/         # 主人公 / 主要人物 / キーパーソン / サブ
│   └── プロット/             # 全体（マクロ）/ 巻別 / キャラ別（三層）
├── manuscript/               # 原稿（draft → revised → final）
└── 素材/                     # 非正典の素材・思考過程・スキル参照資料
    ├── 設計記録/             # 「なぜそう設計したか」の理由記録

    ├── ノート/               # アイデア・没シーン
    ├── 参照/                 # スキルが読み込む補助資料（文章技法・ナレーターボイス詳細）

```

- `設計/` = 正典（canon）。`素材/` = 非正典（背景・思考過程）。矛盾したら正典が優先。
- `.claude/` と `manuscript/` は英語名（ツール互換のため）。`設計/`・`素材/` は日本語名（ニュアンス保持のため）。
- **エージェント・スキルは実ファイルで置く**（symlink を使わない）。Windows では symlink が壊れやすいため、リポジトリが自己完結するよう実体を直接 git 管理する。
