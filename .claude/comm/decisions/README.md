# Decision Queue — 判断の非同期キュー

作者（こうだいさん）の判断が要る点で作業を止めないための書き溜め場。outbox（連絡）と分離した「判断専用レーン」。

料理中に「調味料どれにするか」で手が止まったら、付箋に書いて貼っておき、先に別の下ごしらえを進める——そういう使い方をする場所。

## ファイルと書込権限（単一書込者原則 — `../README.md` と同じ）

| ファイル         | 書く人                                     | 読む人 |
| ---------------- | ------------------------------------------ | ------ |
| `chat-<name>.md` | そのチャットのみ                           | 全員   |
| `ANSWERS.md`     | 作者（または転記を任された chat-main）のみ | 全員   |

## エントリ形式（依頼側）

```markdown
### D-YYYYMMDD-<chat略称>-<連番>: <問いを 1 行>

- 背景: <対象ファイル:行 / 関連する設計文書 / 1 行で>
- A: <選択肢>（推奨 — 理由 1 行）
- B: <選択肢>
- 放置時: <安全側の挙動。「この作業を保留して次へ」等。無回答で作業が勝手に進む選択肢を置かない>
- 期限感: <merge 前まで / 次の執筆前まで / いつでも>
```

チャット略称はレーン表（`../README.md`）の D-ID 略称欄を使う（main / char / org / story / audit / autow / autov）。

## 回答形式（ANSWERS.md・1 行/件）

```markdown
- D-20260802-story-1: A（一言あれば続ける）
```

## 運用

- 依頼側はエントリを書いたら**その判断をブロックせず次の作業単位へ進む**
- セッション開始時に ANSWERS.md を確認。自分宛の回答があれば、エントリを自分のファイルから削除して着手（ANSWERS.md 側の行は消さない — 監査ログを兼ねる）
- 月次で `../archive/YYYY-MM/` へ退避（outbox と同じローリング）
- ここに書いてよいのは「A/B に割れる判断」だけ。**不可逆操作（ファイル削除・正典の大規模書き換え・git 履歴の改変）はキュー不可** — 従来どおり同期で作者確認する

## 本プロジェクト固有: 【未定】設定に当たったとき

`setting-reference.md` により、【未定】の設定で本文を書くことはできない。執筆・設計中に【未定】へ突き当たったら:

1. 決め方が A/B に割れるなら、ここに D エントリとして書き溜める（選択肢と推奨を添える）
2. その作業単位はスキップし、【未定】に依存しない別の話・別の設計作業へ進む
3. 回答が来たら、該当の設計ファイルと MEMORY.md への反映を**提案**してから（承認後に）執筆に戻る

auto-writing / auto-verify のような自動ループレーンは、この運用で「【未定】に当たって停止」ではなく「書き溜めて次へ」を基本動作にする。
