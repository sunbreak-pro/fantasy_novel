## 共通手順（ループ1周）

1. **同期と受信確認**: `git fetch origin` → `git merge origin/main`。`decisions/ANSWERS.md` に自分宛（char / org / story）の回答があれば、自分の decisions ファイルから消して反映をこの周の最優先にする。各 outbox の `@chat-<自分>`・`@all` を確認する。初回の周だけ `/session-start` を通す。
2. **作業1単位**: 自分のスコープ（下記）から未完了の項目を上から一つ選び、ドラフトを書き切る。
3. **承認待ち化**: 下の「承認待ちの作り方」に従い、D エントリと commit（区切りで PR）まで済ませる。
4. **停止判定**: スコープ全項目が承認待ち化済み → 停止して outbox に完了報告。作者の回答待ちだけで進める作業が無い → 停止して未回答 D-ID 一覧を報告。同じ単位が2周連続で失敗 → 停止して状況報告。

## 承認待ちの作り方（このスプリントの核）

- **核の判断は D エントリ**: 名前・人物像の方向・制度の方向など、作品の顔になる判断は方向性の異なる2〜3案＋推奨1行で `decisions/chat-<自分>.md` に積む（書式 → `decisions/README.md`）。
- **ドラフトは推奨案ベースで細部まで書き切る**: 選択肢だけ出して止まらない。推奨案を前提に、そのまま採用できる粒度まで書く。ファイル冒頭に `Status: PROPOSED（承認待ち・関連 D-ID を列挙）` を付け、核の判断が別案に変わったら差し替える前提を明記する。
- **PR で提出**: 自分のブランチに commit し、1〜3ファイルのまとまりごとに `gh pr create` で main への PR を出す（タイトル英語・本文に関連 D-ID とファイル一覧）。マージ判断は作者と chat-main。
- **触ってよい場所**: 自分のスコープの `設計/` 配下・`素材/`・自分の comm ファイルのみ。`MEMORY.md`・`.claude/rules/`・他レーンのスコープは触らない（反映依頼は outbox で @chat-main へ）。
- **【未定】の扱い**: 他レーンの担当に依存する箇所は埋めずに【未定・◯◯レーン待ち】と明記して穴のまま残す。
- **文章は平易に書く**（2026-08-02 作者指示・全レーン共通）: 硬い言い回し・難しい言葉・複雑な文構造を避け、日常の言葉でかみ砕く。既存ドラフトも触るついでに直す。機能的記法（【確定】タグ・表・D-ID）は維持してよい。

## 原作者欲求ファーストの守り方

キャラ・敵の核を世界設定から逆算しない。D エントリの選択肢は「世界の都合でこうなる」ではなく「どんな人物・どんな場面が見たいか」（読者に何を感じさせるか・テラと何をぶつけ合うか）で立てる。世界との整合チェックはドラフトの最後に別工程として一段だけ行い、衝突したら整合側を D エントリで相談する（欲求側を黙って削らない）。

## characters スコープ（chat-characters・`設計/キャラクター/`）

各シートに**「テラをどう見ているか」欄を必ず入れる**（周囲の目線＝主人公への評価の人物側。測定「平均的」評価・孤児という立場をどう扱ってくるか）。新規キャラの番号は c-005 から連番。`_index.md` の更新もスコープに含む。

1. **c-004 幼馴染（ヒロイン）の肉付け**: 名前候補（D）・内面・テラとの関係の質感・王都行きを告げた一週間の心情の骨子。`主要人物/c-004_幼馴染.md` を肉付け。
2. **孤児仲間の顔ぶれ**: 第1章の日常を構成する主要2〜4人（人数と顔ぶれ案は D）。名前・役割・テラとの関係・日常の空気の担い方。`サブ/`（新設可）に c-005〜。崩壊での生死は story レーンの崩壊事件設計に従う（シートには案として記載し、outbox で story と整合を取る）。
3. **領主**: 名前候補（D）・人物像・民との関係・若き日にガルドを観察した接点の具体。`キーパーソン/`（新設可）にシート化。
4. **町の大人たち**: テラの生活圏に必要な最小の顔ぶれ（誰の下で働き、誰に世話になるか）。シート化は主要1〜2人まで、残りは脇役リストとして c-004 等のシート末尾か一覧に置く（過剰シート化しない）。
5. **悪意の法術使いのシートは作らない**: 正体の骨子は story レーンの担当。骨子の承認後に着手する（今回は対象外と outbox で宣言だけする）。

## organizations スコープ（chat-organizations・`設計/世界/社会/`ほか）

主人公に対する**評価の仕組み（評価基盤）**を制度側から細部まで固める。

0. **二つの教えの核**（2026-08-02 作者指示で先行追加・実施済み）: 神の在り方・各組織の正式名称・正義と正義の対立・一地域一教の原則。D-20260802-org-4〜7 とドラフト（`宗教と教会.md`・PR #15）まで完了。残: 教えの分布の粒度（国ごとか土地ごとか）と、テラの町・王都がどちらの教えか（新規【未定】・D 化して作者へ）。
1. **測定の儀の詳細**: 名称・作法・実施主体（教会）・評価階調の運用・記録の残り方・「才能あり」「平均的」評価がその後の進路に与える影響。`宗教と教会.md` を拡充。
2. **王都修行組の選抜制度**: 誰が選び・どう告げられ・半年後の出立まで何が起きる建て付けか（制度の器のみ。半年の空白の中身＝F-005 は story 担当）。置き場は `才能社会の構造.md` か新規ファイル。
3. **才能社会と町の共同体**: 孤児の位置づけ・領主と民の関係・「灯がすべてを決める」風潮を抑える機構の提案（MEMORY 未定欄の解消案・D）。`才能社会の構造.md` を拡充。
4. **討伐同盟の第1章時点の見え方**: 遠景としての存在感と、雑用係・少年兵制度の入り口（第2〜3章への接続。評価・位の運用は `討伐位.md` と整合させる）。`討伐同盟.md` を拡充。
5. **生活基盤の組織**（2026-08-02 作者指示で追加・執筆解禁前まででよい）: 市場の流れ（物流・商い）・医療組織（治し手は法術か薬か）。置き場は `設計/世界/社会/` 新規ファイル。
6. **国名・町名・主要都市**（同上）: 主人公の国の名・テラの町の名・王都の名・その他主要都市。生活感が見える粒度で `設計/世界/地理/舞台の地理.md` を拡充。
